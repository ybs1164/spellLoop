# 연쇄·대상 곱 기믹 성능 전수조사 (2026-11-06)

연쇄 카드(타격 시·행동 완료 시·깃털·모래시계·성배·뿔피리·가시 갑옷·공명의 종)와 대상 카드로 슬롯을 다른 개체에 퍼뜨리는 곱 방식 기믹을 C 시뮬레이션으로 전부 실행해 틱 시간과 로직 포화 지표를 쟀다. 쿨타임·성능 조정의 기준 자료다. 표 전체: [generated/gimmick-perf/tables.md](generated/gimmick-perf/tables.md), 조합별 원자료: [generated/gimmick-perf/all.csv](generated/gimmick-perf/all.csv)·`*.jsonl`.

## 측정 방법

- 도구: [c/tools/gimmick_bench.c](../c/tools/gimmick_bench.c)(덱 하나 = 새 월드 하나), [c/tools/gimmick_census.py](../c/tools/gimmick_census.py)(조합 생성·병렬 실행), [c/tools/gimmick_report.py](../c/tools/gimmick_report.py)(집계).
- 장면: 1단계, 스폰·보스 없음, 적 200마리(grunt·runner·brute, 체력 40%로 고정해 죽지 않음 → 성배·마무리 대상이 항상 통과하는 최악 조건), 보석 40, 화약통 3, 플레이어 무적·원 이동, `쓰러진 자리`는 0.1초마다 하나씩(지속 처치 흉내). 덱은 이동 슬롯 뒤 첫 슬롯 하나.
- 시간: L1·호스트·L2(적 → 표식)는 10초, 나머지는 8초를 돌렸다. 덱마다 실제 시간 한도(5초/2.5초)를 넘으면 중단하고 `시간초과`로 적는다.
- 지표: 평균 틱 ms, **최악 0.5초 평균 ms(등급 기준)**, 최대 개체 수, 연쇄 슬롯 수, 이벤트 대기열 적체, 대상 상한(2048) 초과, 개체·슬롯 풀 고갈.

### 수치 환산

전수조사는 6개 프로세스를 동시에 돌려 측정값이 부풀었다. 무작위 245조합을 단독으로 다시 잰 결과와 WASM(같은 측정기를 emcc `-O3 -flto -msimd128`로 빌드해 node에서 실행) 보정은 다음과 같다.

| 기준 | 전수조사 값 대비 |
|---|---|
| 단독 네이티브 | × 0.21 ~ 0.36 (중앙값 약 0.3) |
| 웹(WASM) | 단독 네이티브 × 약 2.0 → 전수조사 값 × 약 0.6 |

등급은 전수조사 값의 최악 0.5초 평균으로 매겼다. 웹 환산은 대략 다음과 같다(렌더 비용 별도).

| 등급 | 전수조사 ms | 웹 sim 환산 |
|---|---|---|
| 안전 | < 1.5 | < ~0.9ms |
| 주의 | 1.5 ~ 3 | ~0.9 ~ 1.8ms |
| 위험 | 3 ~ 8 | ~1.8 ~ 5ms (렌더와 합치면 프레임 저하 시작) |
| 붕괴 | ≥ 8 또는 시간초과 | ≥ ~5ms, 시간초과는 60Hz 유지 불가 |

표본의 등급 일치율은 74%(182/245)로, 경계 부근 조합은 한 등급 정도 흔들릴 수 있다. 붕괴의 대부분은 시간초과라 환산과 무관하게 확정이다.

## 결론

### 1. 비용은 「호스트 수 × 뒤 대상 수 × 행동이 만드는 개체 수」의 곱이다

- **호스트 수**: 앞 [대상 → 행동]이 연쇄 슬롯을 설치하는 개체 수. 즉발 행동은 맞은 대상 전부, 생성 행동은 만든 개체 전부. 측정 최대: 포탑 1600, 기사 1400, 탄환 1500(부메랑), 장판 600, 적은 화면의 적 전부(이번 장면 200, 실제 판에서는 더 많다). 설치된 연쇄 슬롯은 수명이 없어(`link_expires = 0`) 적·설치물이 살아 있는 한 계속 쌓인다.
- **뒤 대상 수**: L2 집계에서 붕괴 비율이 `마무리 대상` 60% · `전체` 56% · `적` 55%로 압도적이고, `탄환` 22% · `설치물` 14% · `쓰러진 자리` 15%가 뒤를 잇는다. 단일 대상(`가장 가까운 적` 3%, `사냥감` 2%, `직전 표적` 2%)과 `이벤트 상대`·`행동 주체`(0%)는 거의 안전하다.
- **행동이 만드는 개체**: 분열 33% · 기사 소환 30% · 포탑 30% · 궁수 29% · 미끼 25% · 소용돌이·부유 구체 23%가 가장 위험하다. 생성물이 다시 「전체」 대상에 잡혀 다음 회차에 또 복제되는 자기 증식 때문이다. 즉발 행동(흡혈 5%, 위치 교환 8%, 질주 7%)은 낮다.

### 2. 조건형 연쇄 카드가 이벤트형보다 훨씬 위험하다

| 연쇄 카드 | 붕괴 % | 위험 % |
|---|---:|---:|
| 포위의 뿔피리 | 25.8 | 13.2 |
| 고요의 모래시계 | 24.2 | 10.8 |
| 질주의 깃털 | 20.2 | 10.5 |
| 공명의 종 | 19.7 | 5.6 |
| 가시 갑옷 | 15.5 | 8.2 |
| 피의 성배 | 15.3 | 6.3 |
| 행동 완료 시 | 7.3 | 5.2 |
| 타격 시 | 3.3 | 5.8 |

조건형(깃털·모래시계·성배·뿔피리)은 호스트마다 쿨타임이 돌 때마다 발동하므로 사실상 「호스트 수 ÷ 쿨타임」 회/초로 실행된다. 쿨타임 가산(+0.15~+0.8)이 호스트 수를 따라가지 못한다. 이벤트형은 사건이 있어야 발동해 덜하지만, 아군·설치물 호스트의 「행동 완료 시」는 붕괴 13~15%로 올라간다(포탑·기사가 자주 행동을 끝낸다). 가시 갑옷·공명의 종은 「뒤 대상」 전체의 피격·작동을 듣기 때문에 뒤 대상이 `적`·`전체`이면 적 200 × 호스트 수만큼 이벤트가 생긴다.

### 3. 연쇄 없이도 붕괴하는 단일 슬롯이 있다 (L1 11조합)

`전체`·`적`·`마무리 대상` → `궁수 소환`·`기사 소환`·`포탑`·`미끼`. 「전체」가 아군·설치물을 포함하므로 소환할 때마다 대상이 늘어 소환체가 기하급수로 쌓인다(전체 → 기사 소환: 아군 3372). 「적」은 시전마다 적 수만큼 생성해 수명 동안 누적된다.

### 4. 3단 중첩은 한 틱이 수 초 걸린다

`적 → 표식 → 질주의 깃털 → 플레이어 → 마탄 → 타격 시 → 전체 → 폭발`은 첫 틱 하나가 측정값 약 7초(웹 환산 약 4초)로 게임이 멈춘다. L3 표본의 붕괴 127조합 중 113조합이 첫 연쇄가 질주의 깃털이었다. 첫 연쇄를 「행동 완료 시」로 두면 0조합이었다.

### 측정 중 발견한 낭비

조건형 연쇄 슬롯은 쿨타임이 끝난 뒤 `can_act`(빙결·공포) 검사보다 먼저 대상 선택과 조건 평가를 한다([slots.c run_slot](../c/sim/slots.c)). `적 → 빙결 → 피의 성배 → 전체 → 산탄`은 호스트 200이 모두 얼어 있는 동안 아무것도 쏘지 않는데도 단독 네이티브로 7~12ms/틱을 썼다. 행동 불가 검사를 대상 선택 앞으로 옮기면 사라지는 비용이다(동작은 같다).

## 조정 방향 (다음 단계 후보)

측정 결과만 보면 쿨타임 가산만으로는 곱을 막기 어렵다. 쿨타임이 호스트 수에 비례하지 않기 때문이다. 후보는 다음과 같다.

1. **뒤 대상의 쿨타임을 대상 수에 비례시키기**: `전체`(+1.45)·`적`(+0.9)·`마무리 대상`(+0.4)·`탄환`(+0.8)을 연쇄 뒤에서 쓸 때 더 크게 가산하거나 생성 슬롯에서는 대상 수 상한을 둔다.
2. **생성 행동의 누적 상한**: 기사·궁수·포탑·미끼·구체·분열에 개체당 소환 상한 또는 연쇄 슬롯에서의 생성 쿨타임 배수.
3. **조건형 연쇄 카드 쿨타임 상향**: 깃털·모래시계·뿔피리를 +0.3/+0.15에서 이벤트형보다 크게(혹은 `×` 연산으로) 올린다.
4. **연쇄 슬롯 수명**: 즉발 행동으로 적에게 설치한 연쇄 슬롯에 수명을 주어 누적을 끊는다.
5. **로직 상한 정리**: 대상 2048 잘림·이벤트 지연·개체 풀 고갈이 정상 규칙을 깨므로, 위 조정 뒤에도 남는 조합이 이 상한에 닿지 않는지 같은 도구로 다시 확인한다.

계획에서 바뀐 점:

- `LINK_HOST_FREE`는 32 대신 **8**로 정했다. 32에서는 한 행동이 수백 호스트에 한꺼번에 설치한 연쇄가 첫 발동 때 곱 없이 동시에 터져 시간초과가 남았다.
- 새로 설치된 연쇄 슬롯은 첫 쿨타임을 `쿨타임 × 설치 순번 / LINK_HOST_FREE`로 나눠 건다. 그래서 같은 틱에 모두 터지지 않는다.
- 연쇄 슬롯의 생성 수에는 탄환도 센다. 탄환 분열(`관통탄 → 깃털 → 탄환 → 분열`)이 개체 풀을 채우던 문제를 막는다. 플레이어 슬롯은 탄환을 세지 않는다.
- 0단계에 감시 연쇄(가시 갑옷·공명의 종) 최적화를 더했다. 이번 틱 안에 쿨타임이 끝날 수 없는 감시 슬롯은 사건마다 대상을 다시 고르지 않는다. 결과는 같다. 남은 붕괴의 대부분이 이것이었다.

남은 붕괴 68조합(측정 잡음으로 보이는 저개체 조합 포함)은 대부분 두 가지다.

- **플레이어 이벤트 슬롯의 사건 범람**: `전체 → 폭발` 옆의 `[타격 시/가시 갑옷 → 적 → …]`. 연쇄 슬롯이 아니라 실행 결과 곱이 대상 수에 붙지 않는다. 그런데 폭발 한 번에 수백 개 사건이 생겨 대기열이 3,000~3,700까지 쌓인다.
- **적 호스트 × 조건형 연쇄 → 전체 → 궁수·기사**: 아군이 1,600~3,300까지 쌓인다(시간초과 2).

기본 덱(`가장 가까운 적 → 마탄`, `적 → 마탄`)은 쿨타임이 바뀌지 않았다.

## 재현

```bash
python c/tools/build.py desktop
python c/tools/gimmick_census.py l1
python c/tools/gimmick_census.py hosts
python c/tools/gimmick_census.py l2 enemies,mark
CENSUS_ARGS="--secs 8 --limit 2500" python c/tools/gimmick_census.py l2 enemies,lance
python c/tools/gimmick_report.py > reports/generated/gimmick-perf/tables.md
```

덱 하나를 시간 흐름으로 보려면 `echo "enemies,frost,artifactChalice,all,scatter" | c/build/desktop/amagos_gimmick_bench.exe --trace` (0.5초마다 ms·탄환·연쇄 슬롯·이벤트 수를 stderr로). 조합 목록은 결과 파일에 이미 있는 덱을 건너뛰므로 중단 후 이어서 돌릴 수 있다. 병렬 수는 `CENSUS_WORKERS`(기본 6).
