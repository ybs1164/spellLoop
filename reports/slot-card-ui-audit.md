# 슬롯·행동 카드·UI 분석 (2026-10-04)

## 결론

플레이어·적·아군·설치물·장판·탄환·아이템 모두 슬롯 카드 경로를 갖는다. 다만 모든 동작과 규칙이 카드에 완전히 들어 있지는 않다. 카드가 행동을 활성화하고 공통 실행부가 이동·충돌·상태·수명을 처리하는 구조다. 스탯과 카드로 행동을 정의한다는 규칙은 주요 능동 행동에는 적용되지만, 모든 실행 매개변수가 UI에 공개되지는 않는다.

## 개체별 경로

| 종류 | 실행 경로 | 카드와 독립적인 처리 |
| --- | --- | --- |
| 플레이어 | `SkillDeck.fixedSlots`의 `inputMove`, 일반 `slots` | 피격 무적, 상태/버프 갱신, 체력·사망 |
| 적 | `Enemy.update → EntitySlots.update → Enemy.cardTick` | 상태 타이머, 기존 넉백 속도의 이동·감쇠, 수명 |
| 아군 | `Ally.update → EntitySlots.update → Ally.cardTick` | 상태/격려 타이머, 수명 |
| 설치물 | `Placed.update → EntitySlots.update` | 수명, 격려 타이머, 외부 접촉 피해 판정 |
| 장판 | `EntitySlots.update → Game.cardZoneTick` | 수명, 부착 대상/상태의 공통 관리 |
| 탄환 | `Projectile.update → EntitySlots.update → Projectile.cardTick`; 적 탄환은 `cardHazardTick` | 수명, 피격 목록, 공통 충돌 처리 |
| 보석·아이템 | `Pickup.update → EntitySlots.update → Pickup.cardTick` | 획득량·종류 등의 개체 데이터 |

`entitySlot`이 기본 카드를 생성하고 행동별 `EntitySlot`로 분리한다. 일반 행동은 해당 카드의 불변 `effect`와 발동 개체 스탯을 사용한다. 기존 `check-entity-card-values.cjs`는 모든 적·아군·설치물 종류, 장판 종류, 대표 탄환·아이템을 생성하고 별도 숨겨진 설정 저장소가 없음을 확인한다. 카드 제거·전달·독립 편집 검증도 통과했다.

수명은 `tickEntityLifetime`에서 슬롯이 비어 있어도 만료된다. 넉백도 `entityMove` 제거 이후 남아 있는 `kx/ky`로 이동할 수 있다. 이것을 카드 누락으로 볼지 기본 스탯/물리 규칙으로 볼지는 구분해야 한다.

## 잘못되거나 오해를 유발하는 카드

| 항목 | 확인 결과 |
| --- | --- |
| 도주 `entityFlee` | 설명 생성기는 `playerTargeted`이면 '선택한 대상'을 기준으로 도주한다고 표시하지만, `Enemy.cardTick`은 항상 `game.player`의 반대 방향을 사용한다. 대상 교체가 실행에 반영되지 않는 불일치다. |
| 충돌 피해 `entityHit` | UI의 요약은 '같은 대상은 한 번만 타격'이라고 단정한다. 탄환은 `hitSet`을 사용하지만 접촉 개체·공전 칼날에는 반복 타격이 있다. 원문 설명은 이 차이를 설명하므로 요약이 부정확하다. |
| 수명 연장 `prolong` | UI 요약은 '8초간 지속시간을 늘린다'지만 비플레이어 대상은 `castBuff`에서 현재 `life/escT`를 즉시 1.5배 한다. 8초짜리 효과가 아니다. |
| 원소 취약 `entityAffinity` | 이름과 원문은 빙결로 고정되어 있지만 실제 실행은 `effect.elem`을 검사한다. 기본 빙결 구성은 맞지만 다른 원소로 구성하면 설명이 잘못된다. |
| 동일 특수 행동 카드 중복 | 일반 직접 타격은 카드별 수치로 실행되지만 지속 특수 행동은 `enabled: Set`, `effects: Map`에 행동 ID로 합쳐진다. 동일한 `entityKeep` 등을 여러 슬롯에 두면 독립 행동 둘이 아니라 뒤 효과가 앞 효과를 덮는 구조다. |

위 항목은 분석 결과이며 이번 변경에서 전투 규칙은 수정하지 않았다.

## UI 외의 숨겨진 정보

* 도감 스탯에는 최대 체력·이동 속도·공격력·넉백·넉백 저항·수명·범위가 나온다. 개체 `team`은 충돌 카드의 팀 조건과 별개로 존재하지만 도감 스탯에는 직접 표시되지 않는다.
* 카드 `effect`가 실행 원본이어도 `entityCardParametersText`는 모든 필드를 표시하지 않는다. `playerPower`, `rallyPower`, `scaleArea`, `scaleRate`, `blockFear`, `igniteContact`, `mode`, `hazard`, `projectileKind`, `minions`, `deathSplit` 같은 실행 옵션은 일부 전용 설명에만 나타나거나 아예 빠진다. `playerPower`는 플레이어의 공격 배율까지 추가하므로 실제 피해 판단에 중요하다.
* 적의 설치물·아군 접촉 피해에는 `collideStructures`의 0.5초 간격이 하드코딩되어 있다. 탄환 대 플레이어 충돌은 플레이어 반경의 80%를 사용한다. 이 수치는 해당 카드 설명에 없다.
* 거리 유지의 80% 후퇴·115% 접근·60% 측면 이동은 카드 원문에 공개되어 있지만 실행 상수다. 도주의 지그재그 강도 0.7, 진동 계수 0.35와 넉백 감쇠 계수 9는 원문에도 없다.
* 기본 대상 선택 카드들의 탐지 범위 600, 일반 슬롯의 최소 쿨타임 0.6초 및 코스트당 0.35초, 소환 적 수 제한·소환 위치 간격 등 공통 규칙도 개별 카드만 읽어서는 모두 알 수 없다.
* 실행 중 `cooldowns`, `hitSet`, `slotAge`, `pulled`, 귀환 상태 등은 동적 상태이며 별도 UI가 없다. 카드의 고정 매개변수와 구분해야 한다.

## 적용한 UI 변경

`UI.cardName`과 `UI.cardDescription`에서 직접 적힌 거리·반경 수치를 숨긴다. 예를 들어 `거리 260 유지 → 거리 유지`, `반경 350 유인 → 범위 유인`, `거리 260 이내 → 거리 이내`로 표시한다. 아군의 탐지·정지 거리 이름도 같은 방식으로 처리한다.

편집기 카드와 도감 슬롯의 호버에는 원래 이름과 설명을 보존하며, 큰 카드와 편집기의 '스탯' 표시는 키보드 포커스로도 수치를 확인할 수 있다. 유지 거리 260뿐 아니라 실제 후퇴/접근 경계 208/299도 남긴다. 공격 반경을 포함한 직접적인 거리 수치는 툴팁으로 이동하며 시간·수량·피해 배율과 게임 내부 수치는 변경하지 않는다.

## 검증

`tools/check-*.cjs` 전체 22개 중 18개 통과, 4개 실패. 신규 `check-card-distance-ui.cjs`는 편집기·큰 카드·도감의 표시에서 거리 260이 사라지고 툴팁에 유지되며 내부 값이 그대로인지 확인한다. `node --check js/ui.js`도 통과했다.

실패한 검증은 `check-common-action-modes.cjs`(6988/6994), `check-common-mechanics.cjs`(988/994), `check-mechanic-migrations.cjs`(6960/6968), `check-entity-slots.cjs`(undefined/2)다. 앞의 세 건은 피해/타격 기대값, 마지막은 구체의 주기 변경 이후 쿨타임 기대값 불일치다. UI만 변경했고 앞서 실행한 `check-common-mechanics`와 `check-entity-slots`는 수정 전에도 같은 결과로 실패했다. 나머지 두 실패 검증은 변경 후 전체 실행에서 확인했으며, 기대값 노후화인지 실제 회귀인지는 추가로 분리 진단해야 한다.

### 실패 4건 후속 진단 및 수정

네 실패 모두 실제 실행 오류였다. `entityConfiguredCard`가 직접 타격 카드에 부여한 `entityOnly`는 편집/분류용 속성이지만, 실행부는 이를 매 프레임 특수 행동으로 취급했다. 이에 구체·독·심연의 직접 타격이 반복 주기를 무시하고 실행되었으며 쿨타임도 저장되지 않았다. 이제 매 프레임 특수 경로는 `mechanic` 또는 `runsWhileBlocked` 행동에만 사용하고, 직접 타격은 일반 행동 경로에서 주기·쿨타임·이동 후 대상 재평가를 적용한다. 기대 피해값을 낮추거나 검증을 완화하지 않았다.

이 수정 후 `check-common-mechanics`에서 추가로 드러난 지뢰 위치 오류도 수정했다. 기존 카드는 감지한 적을 폭발 대상으로 지정해 적 위치에서 폭발했다. 이제 `생성 후 0.5초 → 거리 58 이내 적 존재 → 슬롯 주인 → 폭발` 카드 체인으로 감지 조건과 폭발 위치를 분리한다. 적이 없거나 감지 범위 밖이면 폭발하지 않으며, 범위 안으로 들어오면 지뢰 위치에서 폭발하는 회귀 검증을 추가했다.

수정 후 전체 22개 검증이 통과했다.
