## 1. 감사 범위와 현재 확인 결과

`c/core`, `c/data`, `c/sim` 전체 모듈, `c/render`, `c/platform`, 빌드·PGO·벤치마크·저장 경로와 Pages 워크플로를 점검했다. JS는 기존 결과와 비교 정책을 참고했다. 게임 소스·CSV는 수정하지 않았고, 현재 C 웹 빌드와 네이티브 시험, 별도 계측 웹 빌드를 실행했다.

## 5. 먼저 보강할 측정·회귀 기준

1. **비교 기준 고정:** 현재 소스·CSV·PGO·바이너리와 저장 샘플을 스냅샷으로 남긴다. 기존 replay 도구의 `baseline-sim.zip`은 예전 기준이므로, 신규 변경의 기준 C 스냅샷도 별도로 만든다. 같은 시드·입력·틱·해상도끼리 비교한다.
2. **단계·작업량 계측:** grid build 횟수/시간, 셀 그룹 수·점유율·fallback, 후보 방문 수·조회 cap 도달, SIMD skip, 실제 pair/피격 수, 슬롯 조회·실행·캐시 miss, watcher 재구성·이벤트 잔여량을 기록한다. 이번 `realtime.separation=0`은 분리 타이머 미삽입 결과이며 충돌 비용 0이 아니다. 계측 비용을 최종 성능 수치에 섞지 않는다.
3. **빠진 장면 추가:** hi=10k/65k·생존 소수, slot_hi만 큰 장면, 지속 보석·소환·분열·유도탄·설치물, 연쇄 폭발·hurt/complete 감시, 상태·버프가 0%/일부/전체인 장면, 255/256 적 경계, 16개 초과 반지름, 큰 좌표·셀 경계·조회 cap 포화, 장시간 플레이·저장/재개.
4. **효과/정적 장면의 의미 보정:** 현재 effects의 100개 효과·600개 파티클은 동적 150틱 종료 때 대부분 없어져 지속 효과 부하를 대표하지 못한다. 고정 수로 재공급하는 별도 스트레스 장면을 만들고 생성 RNG도 통제한다. offscreen10000은 시뮬레이션을 생략한 정적 렌더 장면이며 0ms를 오프스크린 시뮬레이션 성능으로 쓰지 않는다. UI의 시뮬레이션 값도 측정 오버헤드로 취급한다.
5. **전후 반복:** 예열 후 고정 300틱과 실제 루프 300프레임 이상을 별도 측정, A/B 순서 교대로 최소 5쌍. 프레임당 틱 수·종료 상태가 다른 결과는 동등 작업량 가속률에서 분리한다. 평균·p95·16.67ms 초과율, 부하·메모리·전체 원자료를 남기고 불리한 회차도 보관한다.
6. **GPU·입력·장치:** DPR 1·1.25·2, WebGL1/2·SDL fallback·컨텍스트 복원, 실제 모바일 1종과 데스크톱에서 확인한다. 60/120/144Hz의 보간·따라붙는 효과·resize·포인터 hover/drag도 검사한다. GPU finish 진단을 실제 프레임 루프 측정에 넣지 않는다.

기능 회귀는 네이티브·WASM 규칙 시험, 현재 기준 C와 전체 상태·RNG·이벤트·저장 호환 비교, 독립 공간 참조 시험을 사용한다. 렌더 변경은 DPR별 기존 화면·상태·좌우 반전·효과의 픽셀 비교와 `c/build/site/c` 정적 서버 조작을 통과해야 한다. JS는 규칙 대조용으로 사용하되 기존 C/JS 동작 차이를 억지로 같게 만들지 않는다.

| 5 | B1 재학습·B2/B3 빌드 실험, 필요하면 M2·R7 | 코드 구조 안정화 | 최종 정식 배포 경로 확인; 메모리 구조 변경은 별도 저장 호환 설계 후 진행 |

각 ID를 독립 변경으로 시험하고 이득 없는 변경은 되돌린다. 작은 차이는 사전 측정한 실행 간 변동폭을 넘고 반복 방향이 일관될 때만 채택한다. 초기 실험의 작업 목표는 **현재 C 밀집·탄막 CPU의 추가 10~15% 단축**, **폰트 패키지 크기와 고점 이후 저장 지연 감소**로 잡되 달성 전 보장하지 않는다. 전체 지표가 달라 개선율을 더하지 않는다.

메모리 목표는 M1/M5 이후 실제 peak를 다시 측정해 정한다. 구조를 크게 바꾸는 M2를 처음부터 강행하거나, 65,536개 한도를 낮춰 숫자만 줄이는 방식은 계획에 포함하지 않는다.

## 7. 현재 보류할 접근

- 밀어내기·피해의 병렬화, 충돌 순서 재정렬, 화면 밖 틱 생략, 틱 주기 낮추기, 조회 cap 축소: 규칙/결정성을 바꾸므로 현재 동일 동작 최적화 범위에서 보류.
- `fast-math`, 근사 역수·거리·삼각함수, 투명 레이어/블렌딩 순서 변경: 상태·화면 동등성 제약을 넘는 별도 선택 사항.
- Worker/스레드·WebGPU·렌더러 전체 교체: 현재 작은 실제 CPU 시간과 단일 월드·전역 scratch·`g_ctx` 구조를 고려하면 우선순위 낮음; cross-origin isolation 없는 정적 호스팅도 유지해야 함.
- 강제 함수 분리, 근거 없는 셀 조회 캐시 재도입: 직전 불리한 반복 실험을 먼저 참고; 함수 이름이나 코드 길이만 보고 적용하지 않음.
- core RNG 변경·상호작용 덱 편집 로직 전면 재작성·JS 최적화 확대: 현재 C 병목 근거가 약하며, 인게임 스탯·슬롯·카드 스택 모델을 우회할 이유가 없음.

가장 먼저 구현할 묶음은 **S1·S2·S9**, 그다음 **S5·S6·S14**다. 로딩/메모리 체감 개선을 함께 원하면 **M1**을 별도 변경으로 진행하는 것이 합리적이다.
