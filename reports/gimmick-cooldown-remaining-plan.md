# 남은 붕괴 정리: 쿨타임 인상 계획 (2026-11-06)

[1차 적용](gimmick-perf-census.md#적용-결과-같은-날-재측정) 뒤 남은 위험·붕괴를 기존 쿨타임을 늘리는 방식으로 정리한다. 새 규칙은 하나만 더한다(4절의 헛발동 쿨타임). 이것은 쿨타임으로는 줄지 않는 계열에만 필요하다.

## 1. 남은 조합 다시 판정

1차 적용 뒤 위험·붕괴였던 373조합을 같은 조건으로 한 번 더 재고, 두 번 중 작은 값으로 판정했다. 잡음은 값을 키우기만 하기 때문이다. 그 결과 **붕괴 13 · 위험 89 = 102조합**이 남았다(나머지 271은 측정 잡음으로 안전·주의). 원자료: `generated/gimmick-perf-after/recheck*.jsonl`.

| 계열 | 조합 | 형태 | 원인 |
|---|---:|---|---|
| A 소환 누적 | 33 | 적 호스트 → 조건형 연쇄(뿔피리·모래시계·깃털·성배) → 전체·적·마무리 대상 → 궁수·기사·포탑 | 호스트마다 첫 발동 때 수백 체를 소환한다. 아군 1,600~3,300이 쌓인다 |
| B2 가시 갑옷 사건 범람 | 53 | `전체 → 폭발` 옆 `[가시 갑옷 → 적·전체·마무리 대상 → 아무 행동]` | 폭발 한 번에 피격 사건이 250개 나오고, 감시 슬롯이 준비돼 있는 동안 사건마다 대상 200을 다시 고른다 |
| C 적 호스트 가시 갑옷 | 10 | `[가시 갑옷 → 가장 가까운 적 → 충격파·폭발]` | 같은 원리. 감시 슬롯 최적화 뒤 재측정에서는 모두 안전 |
| B 헛발동 | 5 | `[타격 시/가시 갑옷 → 적 → 집중]`, `… → 분열` | 아래 3절 |
| 기타 | 1 | `뿔피리 → 마무리 대상 → 집중` | 위험 |

## 2. 실험: 쿨타임만 올렸을 때

102조합을 같은 세션에서 4가지 설정으로 쟀다(6병렬, 8초). 같은 세션 안의 상대 비교다. 기준 실행(exp0)은 이 세션의 잡음 때문에 1절보다 붕괴가 많게 나왔다.

| 설정 | 안전 | 주의 | 위험 | 붕괴 |
|---|---:|---:|---:|---:|
| exp0 현재 | 10 | 1 | 40 | 51 |
| exp1 조건형 연쇄 곱 인상 | 12 | 9 | 71 | 10 |
| **exp2 exp1 + 소환 곱 인상** | 12 | 9 | 74 | **7** |
| exp3 exp2 + `LINK_SPAWN_FREE` 8→4 | 12 | 7 | 72 | 11 |

계열별 붕괴(exp0 → exp2): A 소환 10 → **0**, B2 가시 갑옷 36 → 2, C 0 → 0, **B 헛발동 5 → 5**. exp3(생성 수 기준 축소)은 효과가 없어 쓰지 않는다. exp2에 남은 붕괴 7은 전부 행동이 집중·분열인 헛발동이다(가시 갑옷 → 집중 3, 분열 1, 타격 시 → 집중 2 등).

대표 조합(최악 0.5초 ms, 전수조사 척도):

| 조합 | exp0 | exp2 |
|---|---:|---:|
| 적 → 표식 → 모래시계 → 전체 → 궁수 | 24.0 시간초과 | 3.3 |
| 적 → 표식 → 뿔피리 → 전체 → 궁수 | 17.6 시간초과 | 2.0 |
| 전체 → 폭발 ‖ 가시 갑옷 → 마무리 대상 → 번개 | 12.8 | 6.9 |
| 전체 → 폭발 ‖ 타격 시 → 적 → 집중 | 46.2 시간초과 | 40.2 시간초과 |

## 3. 쿨타임으로 안 줄어드는 계열: 헛발동

`[타격 시 → 적 → 집중]`에서 집중은 쏘거나 소환하는 적에게만 걸린다. 이 장면의 적(grunt·runner·brute)은 해당하지 않아 행동 대상이 0이 된다. 그러면 현재 규칙(「대상이 없으면 쿨타임을 쓰지 않는다」)대로 쿨타임이 걸리지 않는다. 그래서 타격 사건마다(대기열 3,700개) 적 200을 다시 고르고, 적마다 `enemy_types__props` 표를 문자열로 훑는다. 실제로 아무 일도 하지 않으면서 측정값 30~46ms를 쓴다. 쿨타임 값을 아무리 올려도 쿨타임이 시작되지 않으니 그대로다. 분열(분열로 생긴 개체는 다시 분열하지 않음)도 같은 경우다.

## 4. 계획

### 4.1 쿨타임 곱 인상 (exp2 그대로)

| 카드 | 지금 | 변경 | 범위 |
|---|---|---|---|
| 포위의 뿔피리 | +0.15 ×1.75 | +0.15 **×3** | 어디서나 |
| 고요의 모래시계 | +0.3 ×1.25 | +0.3 **×2.5** | 어디서나 |
| 질주의 깃털 | +0.3 ×1.5 | +0.3 **×2** | 어디서나 |
| 피의 성배 | +0.8 ×1.25 | +0.8 **×2** | 어디서나 |
| 가시 갑옷 | +0.6 | +0.6 **×2** (신규) | 어디서나 |
| 공명의 종 | +0.25 | +0.25 **×1.5** (신규) | 어디서나 |
| 기사 소환 | +0.45 ×2.25 | +0.45 **×3** | 어디서나 |
| 궁수 소환 | +0.8 ×2 | +0.8 **×3** | 어디서나 |
| 포탑 | +0.2 ×2 | +0.2 **×3** | 어디서나 |

플레이 영향(단일 슬롯 쿨타임):

| 슬롯 | 지금 | 변경 후 |
|---|---:|---:|
| 적 → 기사 소환 | 3.07 | 4.10 |
| 가장 가까운 적 → 포탑 | 0.83 | 1.25 |
| 가시 갑옷 → 플레이어 → 치유 | 1.02 | 2.03 |
| 질주의 깃털 → 전방 지점 → 마탄 | 0.62 | 0.83 |

조건형 연쇄 카드는 곱 범위가 「어디서나」라 플레이어가 맨 앞에 놓은 연쇄 슬롯도 함께 느려진다. B2 계열이 플레이어 슬롯이라 범위를 좁힐 수 없다.

### 4.2 헛발동 쿨타임 (B 계열 전용, 쿨타임 방식)

행동이 모든 대상을 받지 않아 실행하지 못했을 때 짧은 재시도 쿨타임 `RETRY_COOLDOWN`(초기 0.25초)을 건다. 이 단계(`action_applies`)에서 대상이 0이 된 경우에만 적용한다.

- 연쇄 카드 조건(깃털·성배 등)이 대상을 모두 거른 경우는 지금처럼 쿨타임을 쓰지 않는다(규칙 「조건이 대상을 모두 거르면 쿨타임을 쓰지 않는다」 유지).
- 대상 카드가 아무것도 고르지 못한 경우(대상 없음)도 그대로다.
- 효과: 헛발동 슬롯의 시도가 사건마다에서 초당 4회로 준다. 다른 슬롯과 정상 발동에는 영향이 없다.
- 규칙 변경이므로 [MECHANICS](../docs/MECHANICS.md) 쿨타임 절과 규칙 시험에 추가한다.

대안: 집중·분열의 대상 판정을 적 종류별로 미리 계산해 두는 성능 수정이다(동작 불변). 비용은 줄지만 사건마다 대상 200을 고르는 낭비는 남는다. 쿨타임 방식(4.2)을 기본으로 한다.

## 5. 검증

1. `python c/tools/build.py test` 통과.
2. 1차와 같은 전수조사 전체 재실행(L1·호스트·L2 4종·되먹임·L3): `CENSUS_OUT=gimmick-perf-after2`.
3. **목표: 붕괴 0, 시간초과 0.** 판정은 1절처럼 위험·붕괴만 한 번 더 재서 작은 값으로 한다.
4. 위험 계열이 여전히 많으면(예상: B2 약 50조합, 측정 6~7ms ≈ 웹 4ms) 가시 갑옷 곱을 ×3으로 올리는 2차 조정을 따로 판단한다.
5. 기본 덱 쿨타임 불변 확인: `적 → 마탄`, `가장 가까운 적 → 마탄`, `플레이어 → 치유`.
6. C 웹 빌드로 편집기 배지(폭이 넓어진 `+0.15×3` 등) 확인.
