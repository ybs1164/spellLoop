# 전면 C 재작성 계획

목표: 게임 로직·렌더·UI 전체를 C 로 다시 만든다. 대상은 데스크톱·모바일·웹이다. 고정 시드 결과(지문)는 JS 판과 맞추지 않는다. 대신 **규칙(`MECHANICS.md`·`check-*.cjs`)이 같다**는 것을 합격 기준으로 삼는다.

## 0. 결정 사항

| 항목 | 선택 | 이유 |
| --- | --- | --- |
| 언어 | C11, 외부 의존 최소 | 데스크톱·웹은 zig cc, Android 는 NDK clang, iOS 는 Xcode clang 으로 빌드한다 |
| 대상 플랫폼 | Windows · Android · iOS · 웹(WASM, 모바일 브라우저 포함) | 데스크톱 headless 판은 밸런스 테스트에 쓴다 |
| 플랫폼 계층 | **SDL3 + SDL3_ttf** | 네 플랫폼을 모두 공식 지원한다: 터치·멀티터치, 앱 수명주기(백그라운드 전환), 화면 회전, 한글 TTF, Android 에셋 읽기(`SDL_IOStream`). raylib 는 iOS 지원이 비공식이라 뺐다. 대안인 sokol 은 더 얇은 대신 폰트·텍스트 입력을 직접 만들어야 한다 |
| 렌더 | SDL_GPU, 또는 SDL_Renderer 의 지오메트리 배치 | 스프라이트 아틀라스에 모아 한 번에 그린다 (지금 `gl-sprites.js` 와 같은 방식) |
| UI | C 즉시 모드 UI (직접 만든 카드 위젯 + Clay 레이아웃) | 편집기는 드래그 앤 드롭 카드 UI 라 직접 만드는 편이 낫다. 해상도·DPI·세로/가로가 바뀔 때마다 레이아웃을 다시 계산한다 |
| 데이터 원본 | `data/*.csv` → 코드 생성기 → `gen/*.h` 정적 표 | 런타임 CSV 파서가 필요 없어서 모바일의 에셋 경로 문제를 피한다. 밸런스 도구(Python `csv`)와 스프레드시트에서 바로 편집할 수 있다. 개발 빌드만 CSV 를 다시 읽는 핫 리로드를 둔다 |
| 웹에서 남는 JS | emscripten 글루와 플레이 로그 전송(fetch)만 | 브라우저 API 는 JS 를 거쳐야만 쓸 수 있다 |

### 모바일 대응

- **입력**
  - 이동은 가상 스틱으로 한다. 화면 왼쪽 아무 곳이나 누르면 그 자리에 스틱이 생긴다. 키보드에서는 WASD 를 그대로 쓴다.
  - 편집기·보상·일시정지 단축키는 화면 버튼으로도 둔다.
  - 편집기 카드 드래그는 마우스와 터치를 하나의 포인터 이벤트로 처리한다.
- **화면**: 논리 해상도를 기준으로 그리고, 노치 같은 안전 영역만큼 여백을 둔다. 세로·가로 모두 지원하고, 카드·버튼은 최소 44pt 크기로 만든다.
- **수명주기**: 앱이 백그라운드로 가면(`SDL_EVENT_WILL_ENTER_BACKGROUND`) 자동으로 일시정지하고 상태를 저장한다. 돌아오면 일시정지 화면을 띄운다.
- **성능 예산**
  - 중급 휴대폰에서 적 2,000 마리 기준 시뮬레이션 4ms, 렌더 4ms 이내가 목표다.
  - 넘으면 기기 등급에 따라 LOD 주기, 적 상한, 파티클 상한을 조정한다.
  - 발열을 고려해 30/60fps 를 고를 수 있게 한다.
- **빌드**
  - Android: Gradle + NDK (SDL3 의 android-project 템플릿)
  - iOS: Xcode 프로젝트 (Mac 이 필요하다)
  - 웹: emscripten
  - CI 에서는 데스크톱·웹·Android 를 빌드하고, iOS 는 Mac 에서 따로 빌드한다.

### CSV 표 구성

`node tools/export-csv.cjs` (`npm run data:export`) 가 JS 런타임 값에서 만든다. 카드 정의 파일 뒤에서 덧붙는 보정·쿨타임 표가 모두 적용된 값이다. 일반 규칙은 다음과 같다:

- 첫 줄은 열 이름이고, 인코딩은 UTF-8 이다.
- 표 하나에 행 하나가 원소 하나다. 맵이면 `_key` 가 키, 배열이면 `_key` 가 순서다.
- 필드는 모양에 따라 나눠 담는다.
  - 스칼라는 본 표의 열에 둔다.
  - 스칼라 배열은 본 표의 열에 `|` 로 이어 담는다. 빈 배열은 `[]` 로 쓴다.
  - 객체·배열의 배열은 자식 표 `<표>__<필드>.csv` 에 둔다 (열 `_owner`·`_i`).
  - 그 밖의 객체는 속성 표 `<표>__props.csv` 에 둔다 (열 `_row`·`path`·`type`·`value`).
- `_tables.csv` 에 표 모양을, `_schema.csv` 에 열의 형을 적는다. 형은 `num str bool null fn sprite dyn list:<형>` 이고, `inf` 는 무한대다.
- 함수는 `impls.csv` 의 구현 키로 바꾼다. 키의 `kind` 는 다음 넷 중 하나다:
  - `each`: 대상마다 `env.<arg>` 를 호출한다. 17개.
  - `buff`: 버프 `<arg>` 를 건다. 7개.
  - `mechanic`: 개체 기믹 `<arg>` 다. 9개.
  - `custom`: C 로 직접 옮긴다. 71개이고, 원문은 [IMPL_SOURCES.md](IMPL_SOURCES.md) 에 있다.
- `constants.csv` 에는 스칼라 상수 56개를 담는다.
- 내보낼 때 CSV 를 다시 읽어 원본과 같은지 확인한다 (왕복 동일). `npm run data:check` 는 `data/` 가 지금 JS 와 같은지 확인한다. JS 판이 남아 있는 동안 JS 를 고치면 다시 내보낸다.

주요 파일:

| 파일 | 내용 |
| --- | --- |
| `cards.csv` · `cards__props.csv` | 카드 112장. 쿨타임 연산은 `cd` 열(`+0.2` `×3` `=0.016`)에, 효과·고정값·스탯 비율은 props 에 둔다 |
| `action_stat_ratios.csv` · `stat_order.csv` · `entity_period_stats.csv` | 행동별 스탯 비율, 스탯 순서 |
| `enemy_types.csv` (+ `__props`, `__slotRecipes`) · `traits.csv` · `status.csv` · `status_caps.csv` | 적 타입, 속성, 상태 이상 |
| `ally_types.csv` · `placed_types.csv` · `buffs.csv` | 아군, 설치물, 버프 |
| `stages.csv` · `stages__pool.csv` (type·weight·from·pack) · `stages__bosses.csv` · `gimmicks.csv` · `entity_gimmicks.csv` | 스테이지, 웨이브, 보스, 기믹 |
| `target_kinds.csv` · `kind_features.csv` · `slot_cycle.csv` · `event_names.csv` 등 | 슬롯·대상 규칙 표 |

C 쪽 생성기(1단계)는 여기에 참조 무결성 검사를 더한다. 검사 항목은 없는 card_id, `SLOT_CYCLE` 순서 위반, 알 수 없는 impl 키다. 화면 문구(`strings_ko.csv`)는 UI 단계(6)에서 UI 코드의 문자열을 모아 만든다.

## 1. 구조

```
c/
  core/     arena 할당기, 세대 핸들, PCG32 난수, 수학, 고정 시간 간격
  sim/      월드(SoA 풀), 스탯, 슬롯·쿨타임, 대상 선택기, 행동, 이벤트 큐, 공간 격자, 피해·상태, 스폰
  render/   아틀라스, 스프라이트 배치, 이펙트·파티클, 피해 숫자
  ui/       HUD, 레벨업·보상, 편집기, 도감, 개체 조회, 오버레이, 가상 스틱
  platform/ SDL3 진입점(데스크톱·Android·iOS·웹), 입력, 수명주기, 저장, 로그 전송
  tools/    headless 실행기(CLI), CSV → C 코드 생성기
data/       *.csv (원본)
gen/        생성된 헤더 (빌드 산출물)
android/ ios/   플랫폼 프로젝트
tests/      규칙 시험 (check-*.cjs 이식)
```

시뮬레이션(`core/` `sim/`)은 SDL 에 의존하지 않는다. 그래야 headless CLI 와 시험이 모든 플랫폼에서 같은 코드로 돈다.

### 시뮬레이션 핵심 설계 (인게임 규칙: 모든 개체 = 스탯 + 슬롯 + 카드 스택)

- **개체 하나의 표**: 플레이어·적·아군·설치물·투사체·장판·적 탄·보석/아이템을 종류(`kind`) 필드 하나로 구분하는 SoA 풀에 둔다. 좌표·속도·반지름·체력·팀·상태 시간을 필드별 배열로 두고, 세대 핸들(`u32 idx | gen`)로 참조한다. JS 의 `{kind:'enemy', e}` 같은 대상 래퍼는 없앤다.
- **스탯**: `enum Stat` 고정 배열(`attackPower moveSpeed maxHp knockback statusResistance …`)로 둔다. 버프는 「기본값 × 배율」을 프레임마다 다시 계산한다.
- **슬롯과 카드 스택**: `Slot { owner, cards[MAX_SLOT_CARDS], n, cooldown, left, version }` 를 슬롯 풀에 둔다. 쿨타임은 카드의 연산 열을 놓인 순서대로 적용해, 카드를 편집할 때 한 번만 계산한다.
- **카드 = CSV 행 + 함수 포인터 표**
  - 대상 카드 17종은 `TargetSel { fn, params }` 로 바꾼다. 선택기 함수는 결과를 대상 버퍼에 쓴다.
  - 행동 카드 44종은 `ActionFn(World*, Actor, Target*, n, ActionParams*)` 형태의 C 함수 하나씩이다. `impl` 이름에서 함수로 가는 표는 생성기가 만든다.
  - 연쇄 카드와 이벤트(`타격 시` `행동 완료 시` `피격 시` …)는 링 버퍼 이벤트 큐에 쌓고, 프레임 끝에서 예산 안에서 처리한다 (`SLOT_EVENT_BUDGET` 유지).
  - 필터·조건(`test/quick/near/gate/when/rule`)은 `custom` 구현 키마다 C 함수 하나씩 둔다.
- **프레임 순서**: 지금 `Game.step` 의 순서를 그대로 옮긴다: 스폰 → 버프 → 슬롯(전 개체) → 이동 → 격자 → 겹침 해소 → 투사체·탄 충돌 → 상태 → 사망 → 이벤트 → 병합 → 압축.
- **성능 방침**: 잠든 적(`nap`) 장치는 다시 만들지 않고, 단순 루프로 먼저 측정한다. 목표는 데스크톱에서 적 5,000 마리에 4ms, 모바일은 위의 예산이다. 모자라면 그때 LOD 주기와 수면을 다시 넣는다.

## 3. 위험과 대응

- **분량**: JS 약 9,800줄에 UI 와 플랫폼 계층이 붙는다. 3단계(카드 전체)와 6단계(편집기 UI)가 가장 크다. 카드는 행동별로 쪼개 하나씩 시험과 함께 옮긴다.
- **밸런스가 달라짐**: 지문을 맞추지 않으므로 수치 감각이 달라진다. 4단계에서 스테이지 지표 범위를 비교하고, 8단계에서 GA 를 다시 돌린다.
- **편집기가 작은 화면에 맞지 않음**: 슬롯 6개 × 카드 9장을 휴대폰 세로 화면에 넣기 어렵다. 6단계 전에 모바일 편집기 화면을 먼저 설계한다 (예: 슬롯 하나씩 펼쳐 보기, 보관함은 아래 서랍).
- **모바일 성능·발열**: 1단계부터 Android 실기기에서 프레임 시간을 계속 잰다.
- **iOS 빌드 환경**: Mac 과 개발자 계정이 필요하다. 없으면 8단계 iOS 는 미룬다.
- **CSV 의 표현력**: 조건·인자가 복잡한 카드는 여러 표에 흩어지기 쉽다. 생성기의 무결성 검사와, 카드 하나를 모아 보여 주는 덤프 명령(`gen --card <id>`)으로 보완한다.
- **콘텐츠 추가가 느려짐**: 새 카드는 CSV 와 C 행동 함수를 둘 다 고치고 다시 빌드해야 한다. 행동 함수는 가능한 한 공통 부품(투사체·장판·상태·소환)의 인자 조합으로 만들어, 대부분의 카드를 CSV 만으로 추가할 수 있게 한다 (`each`·`buff`·`mechanic` 은 이미 CSV 의 `arg` 만으로 구분된다).
- **한글 텍스트**: 폰트 아틀라스에 넣을 글자를 `strings_ko.csv` 와 카드 문자열에서 미리 모아 굽는다.

### 4단계 결과

- 판 진행 (`c/sim/game.c`): 단계마다 그 단계 스테이지를 무작위로 고르는 진행 순서(rollStageRoute), 단계 시간 기준 스폰·체력 상승, `stages__bosses` 시각의 보스 출현 배너(보스 힌트·특성), 보스가 다 나오면 스폰 압박 0.65배, 마지막 보스 처치 → `CLEAR_DELAY` 뒤 다음 단계(적·적 탄·적 장판 정리, 흔들림) → 3단계 돌파면 승리. 시작 화약통 3개, 배너는 제목·부제·색을 갖는 일반형(JS showBanner).
- 보상: 레벨업·보물 상자·보스 처치가 보상 목록에 쌓이고 카드 5장을 가중치로 뽑는다(중복 없음, weight 0·개체 전용 제외). 고른 카드는 보관함으로 + 획득 배너.
- 덱 편집 (`c/sim/deck.c`): JS `SkillDeck.move` 규칙 그대로 — 대상→행동→연쇄 순환 칸, 같은 종류 자리 맞바꾸기, 중간 카드를 빼면 뒤 카드 반환(알림), 구성 제약(장화·반지·인장) 거부 사유, 쿨타임은 새 쿨타임 이하로.
- 화면 UI (`c/render/ui.c`): 타이틀·일시정지(스테이지 요약·적 칩·특성 설명·실행 리스트)·쓰러짐/승리·우측 상단 보상 목록(R, 1~5)·카드 편집기(클릭으로 넣고 빼기, 끌어 놓기, 놓을 수 있는 칸 강조, 두 칸 스크롤)·커뮤니티 링크·화면 밖 보스 방향 화살표. CSS 수치(패딩·테두리·여백 겹침·줄바꿈 keep-all)를 그대로 옮겼고, 카드 이름·설명은 `tools/export-csv.cjs` 가 JS UI 함수를 돌려 만든 `data/card_ui.csv` 를 쓴다.
- 확인: `SHOT_UI=pause|editor|reward|gameover|title node tools/shot-js.cjs` (JS, `SHOT_DUMP` 로 요소 위치 목록) 와 `amagos --shot ... --ui ...` (C) 를 나란히 비교해 위치가 1~3px 안에서 같다. 웹 판은 headless 브라우저로 타이틀 → 시작 → 편집기 카드 끌기 → 일시정지를 눌러 확인(콘솔 오류 없음). 규칙 시험 65개(덱 편집·보상·단계 진행 추가).

### 3단계 결과

- 슬롯 해석기를 JS 판(slot-runtime.js·slot-events.js) 구조로 다시 짰다 (`c/sim/slots.c`): 첫 행동까지의 대상 선택 → 조건 연쇄 카드(test·gate) → 작동 조건(when) → 행동 적용 판정(accepts·requires·exclude·supports) → 실행 전 쿨타임 → 행동 → 연쇄. 뒤에 이어진 카드는 행동이 만든 개체(투사체·소환체·설치물)·피격 대상·보이지 않는 이펙트 개체에 연쇄 슬롯으로 붙고 이벤트 큐(틱당 256)로 실행된다. 소환체가 쏜 탄의 적중은 소환체에도 알린다 (attackEventOwner).
- 카드 변형 표(`World.vars`): 개체 레시피가 쓰는 「설정이 붙은 카드」(적 탄·궁수 화살·포탑·구체·장판 저격, 주기 `=0.4` 같은 쿨타임 변형). 저장본에 함께 담긴다.
- 대상 22종·조건 13종·작동 조건 4종·행동 44종·개체 기믹 9종을 모두 연결했다 (카드 함수 108/108). 피해 공통부(방패·원소 취약·갑주·카드 갑옷·보호막·표식), 상태 이상(빙결·속박·공포 합산 상한·저항, 표식·화상 중첩과 0.5초 틱), 카드 버프(분노·질주·집중·증폭·철갑·보호막·치유), 플레이어 능력치 배율.

### 2단계 결과

- 플레이어·적·투사체·보석이 같은 개체 풀을 쓰고, 행동은 모두 슬롯 카드다. 적은 `[self, entityMove]`(플레이어 쪽 이동)와 `[entitySelf, entityHit]`(충돌 피해), 마탄은 투사체를 만들고 투사체도 `entityMove`·`entityHit` 슬롯으로 날아가 맞힌다. 보석은 `[entityInReach, self, entityMove]` 로 플레이어에게 끌려온다. 연쇄 카드의 조건(`test`)은 다음 대상 카드의 결과를 거른다.
- 스테이지 풀·무리·포위 공격 스폰(보스는 4단계), 체력 배율, 넉백·넉백 저항, 관통, 무적 시간, 게임 오버, 경험치·레벨 곡선, 먼 적 재배치, 겹침 해소, 공간 격자.
- 저장본은 개체·슬롯·판 진행 전부다 (복원한 판이 이어서 똑같이 진행하는지 시험한다).
- 카드 함수 구현 15/108. 시작 덱의 `[ahead, orb]` 는 설치물(3단계)이라 아직 작동하지 않는다. 마탄 하나로는 약 70~80초에 죽는다 (`amagos_cli --circle`): 레벨업 보상이 들어가야 판이 이어진다.
- 성능: 한 틱 약 0.035ms (적 50 안팎, 데스크톱).
- 화면 확인: `amagos --shot out.png --ticks N --circle` 이 자동으로 N 틱을 진행한 뒤 한 프레임을 PNG 로 저장한다. HUD 숫자는 SDL 디버그 글꼴(ASCII)이고 한글은 6단계.
